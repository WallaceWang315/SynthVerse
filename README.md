# SynthVerse

对话式音乐灵感工作台，带工具调用与音频反馈的可运行原型。围绕“音色 → 动机 → 和弦 → 短片段”探索，支持深入音色设计、可拖拽的钢琴卷帘、手动和弦编辑、Agent 工具调用、候选试听、撤销/重做及本机保存。

完整的本机与服务器部署步骤见 [部署指南](docs/deployment.md)，包含模型配置、Nginx、HTTPS、后台运行、验收与回滚。

## 本地启动

要求 Node.js 22.12+（本次使用 22.17.0）或受支持的更新 LTS，以及 npm。

```powershell
Set-Location D:\Repos\SynthVerse
npm.cmd ci
npm.cmd run dev
```

打开 http://127.0.0.1:5173 。命令同时启动网页和仅绑定本机的模型网关，固定端口分别为 5173、8787。端口被占用时先关闭此前启动的实例。

## 体验路径

顶部“新建空白想法”会以基础音色、空音符与空和弦开始，重置本次目标、对话及候选参考，保留个人偏好；上一想法自动进入最近 12 个创意收藏，并可立即撤销恢复。创意名称允许在编辑时完全删空，离开输入框或按 Enter 保存，空名称保存为“未命名想法”；Escape 取消本次改名。

1. 按下琴键或 A/S/D/F/G/H/J/K 即发声，按住持续，松开按包络进入尾音；支持同时弹奏多个音。探索波形、明亮度、泛音、起音、尾音及立体宽度。
2. 输入“音色再柔和一点，保留起音”，试听候选再应用。
3. 三个振荡器直接显示当前波形，点击波形缩略图切换声源；波表图随表类型与位置更新。“调音与齐奏”展开单个振荡器的细节，“深入设计声音”提供噪声、低八度声源、滤波与包络、调制和效果。
4. 在钢琴卷帘空白处画音符，拖动移动，拉右边缘改时长。可框选、Shift 多选、方向键微调和数值编辑。
5. 用“长度”扩展到 1–16 小节，调整吸附、缩放和音域；缩短片段不会静默裁掉音符或和弦。
6. 双击和弦时间块（或聚焦后按 Enter）打开构成音钢琴窗口，也可点击“在钢琴窗口编辑构成音”。点击空白行添加音、上下拖动移调、方向键微调、Delete 删除；左侧琴键按住试听。窗口中的根音、性质和转位选项会立即改变草稿音符，点击“应用构成音”后写回工程并可撤销；取消不改变工程。每个和弦支持 3–6 个不同的构成音（MIDI 33–96）。外部表单仍可调整起点和时长；缩短已有和弦腾出空间，或增加小节后添加更多和弦。最多 64 个和弦，不允许重叠。
7. 打开/关闭底部旋律、和弦和低音声部，比较伴奏的作用。手动和弦编辑会打开和弦层。
8. 选中部分音符后输入“写一个忧郁动机”，候选必须保留未选中的音符；允许删除选中音符；取消选择可重新探索整个片段。
9. 锁定节奏后仍可移动音高；已过期或违反锁定的候选不可应用。
10. 展开聊天消息的执行记录，查看工具、耗时和校验结果。演示记录明确标记没有调用模型。
11. 收藏版本，下载工程 JSON、内置音色 JSON、MIDI 或立体声 PCM WAV。

片段为 1–16 小节、4/4，以 C 大调为参考但允许调外音；旋律音高支持 MIDI 21–108，最多 256 个音符。乐理提示通过实际音符与当前时间位置上的和弦计算，属于建议。和弦关闭或空白时，会明确区分拟采用的和声与无伴奏位置。旧版 v1/v2 工程及本机收藏会自动迁移为 v3（稳定音符与和弦 ID），并保留原内容。

## 接入真实模型

默认明确显示“本地规则演示”，不调用语言模型。有限规则用于验证交互，不是 AI 音乐理解，也不能处理任意自然语言。

把 `.env.example` 复制为 `.env`，填写完整 chat-completions-compatible 接口地址、实际模型名与所需密钥，再重启 `npm.cmd run dev`。

```dotenv
MODEL_CHAT_URL=http://127.0.0.1:11434/v1/chat/completions
MODEL_NAME=填入本地服务已有的模型
MODEL_API_KEY=
MODEL_EXECUTION_MODE=agent
```

本地示例要求服务已安装并已下载对应模型。远程地址必须使用 HTTPS。密钥留在本地服务端，不通过 `VITE_*` 配置、不进入前端工程、收藏和导出。网页发送音符、参数、锁定、选区、目标、偏好、手动选择或启用自动引用的近期候选参考及近期对话。模型可请求浏览器渲染候选，并收到真实音频指标；不上传原始音频，不能声称已经听过声音。

Agent 模式提供12类工具，包括工程读取、分析、编辑、候选注册、渲染比较，以及创作规划、单次反馈修正和内置知识检索，快速模式最多6轮工具探索及2轮收尾请求、12次工具调用、8个注册候选、3次音频渲染；双方案比较模式最多10轮工具探索及2轮收尾、18次工具调用、两个初始候选和一次修正，仍最多3次渲染；服务须支持 chat-completions-compatible 的 `tools` / `tool_calls` 消息协议。局部操作按稳定 ID 校验并原子执行，最终回复只能引用本轮已注册的候选 ID，工具永远不直接应用工程。`MODEL_EXECUTION_MODE=direct` 用于不带工具的结构化输出对照；不支持工具的供应商也可明确选择此模式。

DeepSeek 官方域名或 `deepseek-flash/pro/chat/reasoner` 模型名会启用适配：请求显式关闭思考模式，以降低交互延迟，并将每轮输出上限设为 8192 token；其他供应商保持 3200。若供应商仍返回 `reasoning_content`，工具后续请求会在服务端原样回传，不展示或导出思考内容。`finish_reason=length` 会明确报告回复截断，且不会执行该轮可能不完整的工具调用。兼容代理需要支持这些 DeepSeek 请求字段；关闭思考的说明见 [DeepSeek 官方文档](https://api-docs.deepseek.com/guides/thinking_mode/)。

执行记录中的 `model_step` 成功只表示收到模型响应。最终 JSON 与本轮候选 ID 会单独记录 `validate_final_reply`；普通文字、缺字段、多余字段、重复或未注册 ID 都会明确报告。Agent 模式对非空、大小合规的最终回复允许一次格式修正，仍计入当前模式的轮次与时间总限额；修正阶段禁止工具调用，不会重新创建或渲染候选，也不会自动应用或接受虚构 ID。Token 用量是各轮累计值，不是单条请求的上下文长度。记录不包含模型原始回复或思考内容。

快速请求总限时 45 秒，比较模式 90 秒，前端支持取消。执行记录可复查，任务错误明确显示，供应商返回有效 usage 时才统计 token，未实现价格/费用估算。模型失败明确显示错误，不静默伪装为成功。工程改变后，旧候选会因版本不一致而失效。音乐分析包含符号信息与实测 RMS、峰值、削波比例、能量加权频谱重心和4kHz以上能量比例；没有音频理解模型。

## 数据和音频

- 工程、最近12个收藏、12个候选快照及明确填写的目标/偏好保存在 IndexedDB。聊天仅在页面会话保留，手动参考需刷新后重新勾选；默认自动携带最近3个候选，也可关闭。候选可试听、续改或组合；过期候选不能直接覆盖当前工程。
- 浏览器可能清理存储，因此工程下载是必要的独立备份。导入有格式、版本与大小校验。
- 网页音频引擎为 `web-audio-v3`，使用原生 Web Audio：3 振荡器，每个最多 8 声齐奏，独立音量、移调、微调、失谐和声像；基础波形与自主生成的 3 组谐波波表、噪声和低八度声源。
- 两个可开关的串联滤波器（低通/高通/带通/陷波）、音量 ADSR、调制包络、2 个 LFO 和最多 8 条调制连接。明亮度快捷控制额外作用于低通，避免改变高级滤波设置。
- 效果链包含失真、合唱、镶边、相位、延迟、混响、三段 EQ 和压缩；延迟反馈有上限，最终输出有峰值保护。LFO 按音符重启，速度同步以每拍周期数定义。
- 三张振荡器波形图展示各自基础波形或波表形态，使用与音频引擎相同的波表谐波函数；图中不包含齐奏、滤波、调制和效果，不是合成总输出或实时频谱。
- 片段试听先使用 OfflineAudioContext 渲染，再以音频时钟播放，避免 React/UI 定时器影响节拍；编辑会停止当前试听。
- WAV 导出保留尾音，MIDI 导出包含已启用的旋律、和弦与低音。
- 片段与候选试听进行有增益上限的 RMS 电平对齐和峰值限制，以便比较；不是 LUFS 母带处理，WAV 导出保留原始渲染电平。
- 已研究用户提供的 `vital/vital` 源码模块与预设序列化机制。本版参考模块组织，使用独立网页实现，没有编译或复制 Vital DSP，也不能等价还原 Vital 音色。Vital/Serum 原生预设、任意波表/采样、频谱变形、FM 和 MPE 尚未实现，详见 `docs/vital-integration.md`。

## 创作闭环与对照评测

展开“本次目标与参考”，可启用“双方案比较与改进”。候选卡片支持记录反馈、显式保存长期偏好，并展示修改内容、来源与修正依据。实现与使用边界见 [创作 Agent 指南](docs/creative-agent.md)，内置知识见 [音乐知识库](docs/music-knowledge.md)。

运行 `npm.cmd run eval:study` 验证脚本对照与真实浏览器音频管道；`npm.cmd run eval:study:model -- --limit=1 --variants=quick,compare` 使用实际模型。脚本报告不是模型效果提升证据。

## 验证

```powershell
npm.cmd test
npm.cmd run build
npx.cmd playwright install chromium
npm.cmd run test:e2e
npm.cmd run eval
npm.cmd run eval:creative
```

单元测试覆盖命令、锁定、选区、版本、迁移、时值与和弦范围、乐理、MIDI/WAV；模拟上游验证工具执行、错误修正、调用上限和失败记录。浏览器测试覆盖拖动/拉长、多选、手动和弦、音色模块、保存恢复、导出、移动布局和实际音频渲染。50 个工具约束评测案例及真实模型对照评测入口见 `docs/agent-evaluation.md`。模拟服务和确定性案例不代表真实模型质量或用户满意度。

`npm.cmd run preview` 仅展示生产前端构建；真实对话仍需要运行网关并配置对应代理。当前首版是本地开发应用，尚未配置生产身份认证、托管部署或多人服务。

## 项目结构

```text
src/domain.ts             音乐对象、校验、命令、规则候选与乐理
src/synth.ts              合成器参数、波表、起点音色
src/audio.ts              声源、调制、效果、渲染、MIDI/WAV
src/SynthEditor.tsx       分层音色编辑
src/PianoRoll.tsx         钢琴卷帘手势和选区
src/HarmonyEditor.tsx     手动和弦进行与构成音编辑
src/music-edit.ts         移动、拉长与和弦构造
src/storage.ts            本地恢复与工程导入
src/App.tsx               对话、音色、动机、和声及版本交互
services/api/server.ts    可替换的模型网关
services/api/agent.ts     工具执行、上下文分析与脱敏追踪
evals/                    约束案例、评测脚本及报告
tests/                    核心回归与浏览器验证
docs/                     产品定位及原始开发计划
```

工具协议、分支语义和限制见 [Agent 实现](docs/music-agent.md)；12个可导入创作场景、评分表与真实模型对照命令见 [评测指南](docs/agent-evaluation.md)。

下一轮重点：用真实供应商运行 agent/direct 对照与人工试听，测试普通用户任务完成情况；另行验证 Vital 原生或 WASM 引擎接入，逐步补齐采样与高级波表能力。
