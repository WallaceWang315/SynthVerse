# Agent 创作评测指南

2026-10-08。区分三类证据：工具边界回归、模拟模型的真实浏览器闭环、真实模型的创作表现。本轮没有配置或调用真实模型。

## 快速运行

```powershell
npm.cmd test
npm.cmd run eval
npx.cmd playwright install chromium
npm.cmd run eval:creative
npm.cmd run test:e2e
```

- `eval`：50个预构造候选，10类约束各5个变体，检查接受/拒绝。报告：`evals/reports/safety-latest.json`。不调用模型，不渲染音频。
- `eval:creative`：12个独立创作需求，包含一个续改任务。用脚本模拟工具请求，调用实际Agent运行器与Chromium音频渲染。报告：`evals/reports/creative-mock-browser-latest.json`。模拟模型不是LLM，通过率不能写作真实模型质量。
- `test:e2e`：网页实际操作、选区编辑、候选渲染、应用/撤销、参考恢复、取消保护等。桥接单元测试注入已知指标，只验证任务关联；浏览器与创作评测才验证真实音频。

创作评测会生成 `evals/scenarios.json` 和12个 `evals/fixtures/*.project.json`。浏览器评测自行启动临时网页服务，不要求手动启动5173服务；需先安装Playwright的Chromium。没有音频硬件也能离线渲染，离线渲染不等于人工试听。

## 在网页手工使用场景

启动 `npm.cmd run dev`，导入表中工程JSON。每次开始新场景前取消此前选区、清空参考、调整目标/偏好，必要时刷新页面清空聊天；导入保留当前版本序号与撤销能力。输入表中提示。涉及选区时先在钢琴卷帘用选择工具点击末音，涉及节奏锁定时确认锁定开关。默认规则演示仅支持有限关键词，测试完整自然语言任务需要配置支持工具的真实模型。

| 场景 / 对应fixture文件名 | 提问 | 验收重点 |
|---|---|---|
| soft-glass | 玻璃音色柔和一点，保留起音和旋律。 | 亮度降低，起音与旋律保持；两个候选试听比较 |
| soft-glass（续改） | 先点击喜欢候选的“继续”，再输入：继续刚才的候选，尾音再缩短一点。 | 保留参考音色方向、缩短尾音；不自动应用 |
| short-release | 只把尾音缩短到0.2秒，其他参数保持。 | release=0.2，其他参数保持 |
| selected-ending | 只将选中末音改成C5，其余音符和节奏保持。 | 先选中末音；MIDI72，选区外完整保持 |
| locked-transpose | 把所有音符升高一个半音，保留已锁定的节奏和力度。 | fixture已锁节奏；所有音高+1，时序/力度保持 |
| four-chords | 用C、Am、F、G四个和弦覆盖这两小节，每个持续2拍，打开和弦声部。 | 4个和弦，起点0/2/4/6，无重叠，声部开启 |
| harmony-gap | 将第一个和弦缩短为2拍，空出第3和第4拍，保留后面的和弦。 | 第一个和弦时长2，第二个保持，空白合法 |
| advanced-effects | 加一点合唱和混响，保持振荡器、旋律和其他效果设置。 | 效果变化，其他内容保持 |
| explanation-only | 解释最后一个音和当前和弦的关系，给我一条建议，不要生成或应用候选。 | 无候选；解释应对照D4与Am7，避免把延伸音一律称为错误 |
| invalid-correction | 音色柔和一点，亮度设置到24。无效工具参数必须修正后再返回。 | 工具999的无效参数被拒绝，再以24成功；故障由模拟脚本注入，真实模型未必会触发 |
| branch-combination | 先生成柔和音色并选为参考，再生成末音C5的旋律并选为参考；输入：组合我指定的第一个参考的音色和第二个参考的旋律，保留当前和弦。 | 参考组合，新候选绑定当前版本，和弦保持；评测脚本预先提供两个参考 |
| delete-selected | 只删除选中的最后一个音，其他音符不能改变。 | 先选中末音；7个音符，选区外保持 |
| boundary-add | 在第7.5拍添加一个C5，持续0.5拍，力度0.6，不超出两小节。 | 坐标以0起算拍单位；新增音符在7.5–8拍，原音符保持 |

`scenarios.json`包含初始工程、选区ID、明确目标/偏好、操作示例、自动检查清单和人工评分维度。操作示例是用来复现工具执行的参考解，真实模型无需生成完全一样的操作序列。

## 真实模型及无工具对照

配置 `.env` 中MODEL_CHAT_URL、MODEL_NAME、MODEL_API_KEY。需服务支持兼容的tools/tool_calls协议。以下命令会按配置实际调用供应商：

```powershell
npm.cmd run eval:creative:model -- --limit=3 --mode=agent
npm.cmd run eval:creative:model -- --limit=3 --mode=direct
npm.cmd run eval:creative:model -- --limit=12 --mode=compare
```

没有模型配置时立即停止，不降级。compare对同一初始工程分别执行Agent和无工具结构化生成，再用同一浏览器渲染器测量。direct模式没有工具纠错闭环，仍接受同样的补丁边界校验与音频测量。输出各自的候选、trace、token用量（仅供应商提供时）、请求意图检查、续改检查、指标和待人工评分。

真实模型报告在 `evals/reports/creative-{agent|direct|compare}-live-latest.json`。重复运行报告会覆盖latest文件；比较多个运行时先复制为带模型名和日期的文件。统计时区分场景数、模型请求轮数、候选数和重复次数。

旧 `eval:model -- --limit=10 --mode=compare` 仍可运行50个约束变体，但没有浏览器执行器；render_preview明确返回not-rendered。这组自动化仅检查结构和约束，不能作为完整创作表现对照。

## 评分与解释结果

报告的passed由可测量请求字段、注册/工程约束、实际渲染、原工程未改动以及相关续改检查组成。比如亮度24、末音72、四和弦覆盖；部分语义检查允许额外变化，所以passed不能取代完整听感与保留条件复核。没有请求到候选会失败，明确只要求讲解的任务除外。

给每个最终候选填表，隐藏方案来源并随机安排试听顺序；不要把客观指标当成音乐好坏评分。

| 维度 | 0分 | 1分 | 2分 |
|---|---|---|---|
| 请求满足度 | 改错对象或违反要求 | 部分满足，仍有明显遗漏 | 修改与保留要求均满足 |
| 音乐/解释质量 | 不可用或解释错误 | 可用，但解释或听感有问题 | 听感合适，解释依据准确 |
| 创作启发 | 没有帮助 | 提供一个可以继续的想法 | 提供清晰且值得探索的方向 |

记录模型/配置、场景、参考选择、目标、候选ID、试听意见、应用/撤销次数，以及第一次得到满意候选所需时间。失败场景同样保留。新手用户测试可以使用“十分钟内得到一个愿意收藏的短音乐想法”，不要求完成整首歌曲。

当前已执行：53项单元/网关测试、18项Chromium测试、50个工具约束案例、12个模拟模型加真实浏览器渲染场景全部通过。真实模型和人工评分未执行；以上结果不支持任何真实模型成功率、用户满意度或实习效果的声明。
