# 第二、第三阶段：试听反馈与专业协作

## 使用

对话框中的「探索方式」默认快速编辑，兼容旧流程。展开后可选择：

- **试听反馈**：原始版本与最多两个候选使用长音、快速短音、和弦、当前片段四类素材渲染。根据具体观察最多进行一次修正，总候选不超过三个。
- **专业协作**：混合任务先运行作曲专业上下文，再针对最多两个音乐分支分别运行音色专业上下文。通过补丁、来源版本、锁定与选区检查后联合试听。单一领域请求仅调用相关专业。

不同专业具有独立消息列表、工具权限和继承自原始请求的硬约束；使用同一对话模型。统筹是有界的确定性工作流，不是任意自由讨论，也不并行写工程。每个专业阶段最长55秒，共享24次模型调用与18000输出token上限，单次模型响应仍遵守原预算。试听反馈最长180秒、协作最长240秒；最多两个分支和一次反馈修正。用户取消会丢弃迟到结果。

候选中展开「试听依据与专业贡献」可选择素材，对照原始版本，切换原始电平/有限增益音量匹配，查看实际观察、局限和专业贡献，导出修改与分析记录。继续按钮可以只调整音色或音乐结构。

## 音频能力边界

未配置本机模型时，只测量 RMS、峰值、削波、频谱、起始到峰值时间及音符结束后的尾段 RMS。静音与削波提示是具体测量，不是审美判断。模型观察是未校准信息，不会自动变成“好听”的分数。没有问题也不等于满足目标。

没有下载 YuE2、MERT2 或任何模型权重，也没有声称在真实模型或人工盲听中取得质量提升。模型适配器是可运行的接入基础；具体模型的推理依赖和映射须由适配模块提供并单独验证。

音频分析接口只允许字面量 127.0.0.1 或 [::1]，禁用重定向。**云端音频上传未接入**。浏览器将试听音频传给应用后端；部署在其他主机时，“本机”指应用后端所在主机，不能把远程部署描述成所有音频都留在用户设备上。现有模型配置是应用实例级配置，公开多人部署仍需用户隔离。

## 可复现试听

- 固定素材为120 BPM、C4及固定力度；和弦探针由同一合成器演奏四个音，不使用简化伴奏音色。
- 当前片段保留实际速度、音区与声部，最多4小节；探针最多32秒，截断会标记。
- 原始测量在44100 Hz双声道渲染上进行；本机模型传输为16000 Hz单声道16位PCM。因此相位抵消等情况下模型输入与立体声听感可能不同，不能据此判断立体声空间特征。
- 每次创建新音频上下文与效果器，噪声与混响脉冲使用固定种子。Web Audio浮点/压缩处理不承诺逐字节一致，测试使用数值容差。每份实际PCM都有SHA-256哈希。
- 原始与匹配音量WAV仅存在浏览器独立IndexedDB缓存，容量64MB，超限淘汰旧音频。候选档案只保存证据、哈希、补丁与来源。缓存缺失时明确提示，可重放当前片段。
- 演奏配置哈希不同会提示不可将全部差异归因于音色。当前音量匹配有增益与峰值上限，不是严格感知等响归一化。

## 本机模型接入

设置页展开「音频理解模型（独立设置）」，填写实现以下协议的本机接口、模型名称和独立Key。普通文本API不能直接使用。桌面版单独加密保存音频Key；网页开发服务只在本次进程保存。

请求为 `POST /analyze`，协议为 `synthverse-audio-v1`：

```json
{
  "protocol": "synthverse-audio-v1",
  "model": "your-local-model",
  "goal": "保留空灵感，让快速音符更清楚",
  "clips": [{
    "probe": "staccato",
    "engine": "web-audio-v3-probes-1",
    "configId": "演奏配置哈希",
    "truncated": false,
    "durationSeconds": 8,
    "audio": {"encoding": "pcm-s16le", "sampleRate": 16000, "channels": 1, "samples": 128000, "data": "BASE64"},
    "metrics": {"rms": 0.04, "peak": 0.2, "clippingRatio": 0, "spectralCentroidHz": 900, "highFrequencyEnergyRatio": 0.01, "onsetToPeakMs": 30, "tailRms": 0.003}
  }]
}
```

可选 `reference: {name, audio}` 最多12秒。必须将音频实际传入模型，不应只根据目标文本生成评价。响应严格包含：

```json
{
  "findings": [{"code": "tail-overlap", "probe": "staccato", "observation": "基于音频得出的具体观察", "goalRelation": "该观察与目标的关系", "suggestion": "建议验证的有限调整", "startSeconds": 1, "endSeconds": 2}],
  "limitations": ["说明模型能力、参考条件或无法确定的方面"],
  "needsRevision": true
}
```

最多6项观察，时间范围必须落在对应音频内；无观察时不能仅凭 needsRevision 触发修正。超时25秒、格式错误、未知探针、过大响应均退回信号分析。模型文本是非可信观察，不能扩大专业权限。

提供仅用Python标准库的服务外壳：

```powershell
python scripts/local-audio-adapter.py --backend D:/your-model/backend.py --port 9001
```

`backend.py` 必须定义 `analyze(goal, clips, reference)`，返回上述响应。clips 含 probe、sample_rate=16000、samples浮点列表和测量metrics；reference是可选浮点列表。模型可在模块加载时初始化。此脚本不下载、不训练、不安装模型；不提供伪装成模型的规则后端。可用环境变量 AUDIO_ADAPTER_KEY 设置本机鉴权。

## 评测与阶段验收

`evals/listening-scenarios.ts` 提供30个案例：起音、尾音、明亮度、跨专业、参考和无需修改，覆盖五种声音配置；前三种配置用于开发，后两种用于留出评测（18开发、12留出）。

```powershell
npm run eval:listening -- --limit=6
npm run eval:listening -- --limit=30 --variants=role-only,signals,collaborative
npm run eval:listening:model -- --limit=6 --variants=role-only,signals,audio-model,collaborative
```

真实评测需要 MODEL_CHAT_URL、MODEL_NAME；音频模型组还需 AUDIO_ANALYZE_URL（仅本机）、AUDIO_MODEL_NAME，可选 AUDIO_API_KEY。`--live` 会调用配置的对话服务，默认评测不会调用模型或花费模型额度。

输出所有成功和失败、约束、耗时、token、实际音频分析状态、完整候选及空白人工评分CSV。信号组和协作组在未配置音频模型时如实记录 signal-only。脚本控制组只验证工具与真实浏览器渲染管道，不能用于声称模型能力提升。各模式预算不同，应同时比较质量、时延和费用；不提供虚构的货币成本。

**尚待产品效果验收**：选定真实本机模型后运行留出集、组织盲听并填写采用率。未经这些评测，自动修正只作为候选实验，不自动推荐或应用“最佳音色”。
