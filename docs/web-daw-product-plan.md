# SynthVerse 网页轻型 DAW 产品与开发调整

> 2026-10-08 进一步修正：当前目标是让对话模型持续参与创作、提供灵感与乐理辅助，而非完成完整歌曲或复刻 DAW。以 [对话式音乐灵感工作台](conversational-music-workbench.md) 为最新定位基线；本文保留为网页技术方案参考，完整歌曲及轨道数目标不再作为主验收标准。

日期：2026-10-08。定位调整提案；替代原桌面优先计划作为下一轮讨论基线，原 P0/G0 清单保留为原生引擎与桥接研究资料，不作为网页 MVP 的发布门槛。

## 产品目标

让未系统学习音乐制作的用户通过可听见的操作理解合成器，并创作可编辑、可保存、可导出的个人作品。第一价值是快速发声、听懂变化、做出选择；AI 提供候选、解释与局部修改。

建议首发面向桌面 Chrome/Edge，手机先覆盖试听与宏参数体验；其他浏览器与完整移动编辑按实测逐步支持。

## 创作流程

1. 无需账号或 API Key，点击开始即可启动声音。
2. 从声音、节奏、情绪或空白工程开始；提供可关闭的引导。
3. 使用明亮、柔和、宽度、起音、尾音、运动感等宏参数探索声音，展开后可见对应合成参数。
4. 获取 2–4 小节旋律动机与三个和弦候选，保持相同音色试听，比较音乐变化。
5. 增加低音与鼓，组合成八小节循环；锁定满意部分，局部生成变体。
6. 用片段扩展成短作品，保存工程并导出 WAV/MIDI。

界面以声音面板、片段/简化钢琴卷帘和上下文助手构成，进阶时再展开完整时间线与参数。每条乐理建议附应用范围、试听、应用和撤销，不默认改变工程。

## 首版范围

必做：可演奏合成器、宏参数与基础参数、旋律/和弦候选、鼓步进器、四轨八小节、局部锁定、撤销重做、本地自动保存、工程下载/导入、MIDI/WAV 导出、规则型乐理提示。

有限 AI：文字选择/修改音色，按结构化约束生成动机，解释实际应用的变化。模型输出必须经命令校验；离线或无额度时仍能手动创作并使用本地规则与模板。

后续：更多轨道与段落、参考音频分析、云同步、分享、Web MIDI、本地模型接入、外部 Agent。

研究项：Vital DSP 的 WebAssembly 移植、Vital 全量预设兼容、Serum 本地桥接、跨引擎预设重建。任意音频无损转预设不作承诺。

## 创作辅助

- 动机：短、可延展，支持节奏/音高/结尾/力度独立锁定和变体。
- 和弦：先展示听感描述，展开和弦名、级数与声部连接；支持旋律优先与和弦优先。
- 音色：根据声部角色、包络、音域、频谱和当前配器推荐，先固定同一乐句比较音色。
- 乐理：针对当前选区提供简短、可验证的说明；规则计算调内音、和弦音及节奏位置，语言模型负责表达。
- 不把调外音、不协和或切分视作错误；允许关闭吸附与提示，保留创作者选择。
- 解释可追溯到真实命令差异，例如“缩短第 5–8 小节尾音”，不生成无依据的参数说明。

## 技术架构

UI 与项目状态 → 统一命令/撤销层 → 浏览器音乐事件调度 → Web Audio/AudioWorklet 引擎。

后台 Worker 负责分析、候选生成和资源准备；服务器提供模型网关、可选账号/存储及重任务。模型响应和网络不能成为实时播放依赖。

建议 TypeScript 前端；Tone.js 可用于首轮 Transport、乐器与效果原型，复杂 DSP 逐步放入 AudioWorklet，必要时接入 WASM。音符使用音频时钟提前调度，动画和 React 状态不作为节拍时钟。

内部保留 SoundSpec、ClipSpec、Project、GenerationRecord、Job 和可版本化命令。工程保存音符、最终参数、资源和引擎版本，重开无需重新生成。音色格式包含后端能力与专有字段，不宣称各引擎等价。

导出先验证 OfflineAudioContext 与所选引擎的兼容性，再进行 WAV 编码；长工程需要考虑内存、分段或服务器渲染方案。导出保留尾音并明确分轨起点。

## Vital、Serum 与模型接入

Vital 是可选高级引擎。先用小范围试验验证 DSP 与桌面 UI/账户服务解耦、WASM 构建、CPU/内存、多音高输出差异和授权路线，再决定是否移植。下载到浏览器执行的 WASM 也要处理源码及分发许可。

普通网页不能直接加载用户机器上的原生 VST3 二进制。Serum 原插件兼容通过未来可选本地伴随程序实现，处理用户安装、授权、版本、鉴权、来源限制和文件权限。没有伴随程序时，只声明已实现的受限转换或音频导入能力。

模型分为平台托管、用户自带服务、本地模型三个入口。首访不要求配置。BYOK 不把密钥写入工程、日志或默认持久化浏览器存储；直连需供应商 CORS 支持，代理需明确告知密钥和音频流经服务器。长期密钥采用明确授权的服务端加密存储或本地伴随程序凭据库。

浏览器内小模型须按设备性能选择，不作为首版前置。连接 localhost 服务要验证浏览器本地网络权限、HTTPS/混合内容和 CORS；不能承诺填写 URL 即全平台可用。

外部 Agent 后续使用与 UI 相同的受限命令接口：读取上下文、搜索音色、生成片段、预览补丁、应用补丁、导出。绑定用户及项目授权，带版本校验、幂等与撤销。

## 浏览器专项要求

- 用户手势启动 AudioContext，明确静音、挂起与恢复状态。
- 采样、推理与分析不得阻塞音频处理，限制复音、效果链和任务并发。
- 若使用 SharedArrayBuffer/WASM 多线程，提前验证 HTTPS 与跨源隔离及资源加载策略；无需共享内存时采用更简单实现。
- IndexedDB 等本地存储可能被清理，自动保存不等于永久备份；提供工程包下载、资源校验和恢复提示。
- 页面后台、休眠和设备切换需实测；失去时序时安全暂停或重新同步，不承诺后台持续播放。
- 预览使用响度匹配，输出有异常峰值保护；提供键盘操作、参数数值输入与非颜色提示。

## 新开发阶段

以 3–4 名工程师配兼职音乐设计/QA 为估算前提，发布缓冲另计。

| 阶段 | 周期估算 | 交付与验收 |
| --- | --- | --- |
| W0 声音与交互验证 | 1–2 周 | 无模型即可演奏、调参数；证明音频与 UI 分离，四轨循环及离线导出路径可用 |
| W1 合成器体验 | 2–3 周 | 宏参数、包络/滤波、候选 A/B、可听见的教学例子；新用户能解释至少一种声音变化 |
| W2 创作 MVP | 4–6 周 | 动机、和弦、低音/鼓、四轨八小节、编辑/锁定/撤销、保存/导出；端到端无需 AI 也成立 |
| W3 AI 与轻编曲 | 3–5 周 | 语言编辑、更多片段/段落、上下文建议、预算与取消；模型失败不破坏工程或播放 |
| W4 高级兼容 | 独立估算 | Vital/WASM、Serum 桥接、本地模型与 Agent，分别按技术试验决定是否发布 |

W0–W2 预计 7–11 周，是方向估算而非已完成排期。先做新手使用测试再增加功能。

暂定体验目标：在参考机器与网络条件下首次手势后 10 秒内有可玩声音；10 名未学过 DAW 的试用者中至少 8 名在 15 分钟内导出八小节作品；刷新后恢复工程；指定四轨负载中编辑不破坏节拍。具体性能阈值在 W0 实测后冻结。

## 对原计划的影响

- 保留：结构化工程、音色分析、受约束生成、撤销、局部锁定、预算与 Agent 命令设计。
- 提前：浏览器声音反馈、可试听乐理、新手测试、项目备份、设备降级。
- 延后：Windows/VST3 安装分发、Tracktion、Serum 全量兼容及音频反演。
- 开发环境转为前端运行时、浏览器调试与测试；Python 随分析服务加入；MSVC/CMake 等保留给 WASM/原生桥接研究，不阻塞网页原型。
- 首个可验收作品：用户亲自选择声音与动机，调整和弦并加入鼓点，生成能重新打开和继续修改的八小节工程。
