# 第一阶段：专业工作流与可追溯编辑

## 本阶段实现

- 自动按本次请求选择音色、旋律与和声、创作统筹角色；明确意图优先于当前面板。
- 对话输入区显示工作方向和可编辑字段，可手动切换。手动选择不解除锁定或本次保留要求。
- 服务端建立 creationBrief，保存原始要求、背景目标、版本、选区、允许字段与检查项。
- 每个角色使用不同的系统指令和编辑工具列表。通用 propose/revise/compose 和 direct 模式同样通过最终工程差异校验，不能绕过角色权限。
- 保留现有锁定、稳定 ID、选区、比较计划及旧工程版本防覆盖机制。
- 候选 provenance 保存角色、要求、实际变化字段、参数名称、变化音符/和弦 ID 和创建时间。patch 和 project 保存可重放结果；parentIds 仅标记明确引用，不把所有参考自动视为父版本。
- 候选卡可展开查看修改依据；档案使用现有 IndexedDB 保存，旧档案无需迁移。
- 离线规则演示也使用共享字段与节奏校验，并明确不具备音频理解。

## 边界

这是同一基础模型上的角色路由与专业工作流，不是多个模型实例自主并行协商。统筹角色处理混合任务；专业角色交接和真实听觉反馈属于后续阶段。

自动路由采用可解释的中英文关键词及常见中文保留句式，不等同于完整自然语言理解。省略、复杂否定、跨句指代可能需要手动指定工作方向。背景目标作为上下文提供，不自动升级成硬约束；明确锁定仍使用界面锁定。任意声音细节如“保留起音的感觉”目前不会伪装成已验证的听感约束。

第一阶段没有安装 YuE2、MERT2，也没有新增模型调用轮次。音频指标仍不是审美判断。

## 验证

运行 `npm test`、`npm run build`。专业角色测试见 tests/creative-roles.test.ts，浏览器交互见 tests/e2e/creative-roles.spec.ts。

覆盖跨面板路由、保留要求、手动选择、通用工具越权、参考组合越权、实际差异记录、旧候选兼容和工程版本检查。现有回归中的跨领域工具测试需明确使用跨领域任务描述。
