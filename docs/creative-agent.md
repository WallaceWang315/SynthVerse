# 创作 Agent：比较、修正、记忆与检索

## 用户入口

展开聊天区“本次目标与参考”，勾选“双方案比较与改进”。普通快速模式最多6轮工具探索加2轮收尾、12次工具调用、45秒；比较模式最多10轮工具探索加2轮收尾、18次工具调用、90秒，两种模式都最多3次浏览器渲染。直接生成模式是评测基线，不执行工具闭环。

比较模式的创作步骤：

1. `plan_creation`：声明目标、两个方案、检查项及 `preserveFields`；后者由运行时校验，不能静默更改。
2. 可调用 `search_music_knowledge` 检索内置启发式，并将检索 ID 附在候选上。
3. `propose_edit` 注册两个音乐内容不同的候选；仅改标题不算不同方案。
4. `render_preview` 分别渲染，`compare_candidates` 返回参数、音符、指标与检查发现。
5. 根据请求决定是否修正。`revise_candidate` 只能引用源候选实际检查发现，最多一次；继承父候选修改并重新经过当前工程的锁定、选区和版本校验。
6. 修正版再次渲染、比较，最后返回2至3个候选供用户选择。没有发现相关问题则无需修正；纯讲解请求可不生成候选。

最终回复格式修正仍最多一次，该阶段禁止新工具执行；工作流缺步骤另有一次允许调用工具的补齐机会，全部计入同一个总预算。不接受虚构 ID。任务取消或总预算耗尽不会自动应用任何候选。

## 检查边界

- `silence`：实际渲染片段 RMS 小于0.00001；可能是预期留白，不自动视为错误。
- `clipping`：实际削波比例超过0.1%。
- `low-register-density`：启用和弦的工程中，有至少三个 C4 以下构成音；这是符号提示，不是浑浊或质量的声学结论。

浏览器最多渲染前4小节；声学检查仅针对该片段。没有渲染器时只做符号分析，不声称听过音频。真实模型是否选择合适的修正仍需评测，工具通过不等于听感改善。

## 记忆与版本

候选卡片展开“比较依据与反馈”，填写原因并选择喜欢或不合适。反馈携带候选 ID、标题和时间，随下一条消息提供给模型；应用候选也会留下选择记录。点击“记住这条偏好”才加入长期偏好，用户可直接编辑、清空；模型不会自行写入长期记忆。

反馈与偏好保存在本机 IndexedDB；新建空白想法清空当前目标、反馈、候选及对话，保留长期偏好。默认自动携带最近3个候选以支持“第二版”等续聊，也可关闭或手动勾选参考。最近12个候选保留明确引用的父版本 ID，修正版记录修正依据；早期父版本被淘汰后不保证可以恢复，仅保留关系标识。

上下文保留最近6条消息、每条最多1200字符，并另外传递完整当前工程、目标、明确偏好、近期反馈和最多3个参考。参考省去重复 patch 和音频字段，工具消息中的注册结果省去重复的完整工程，只保留可复建的 patch。这是有界上下文整理，不是语义摘要或无限长期记忆。

## 检索

知识库见 [music-knowledge.md](music-knowledge.md)。当前4条自编指南，使用标签检索，没有向量数据库、外部网页检索或未经验证的文献引用。候选引用只能来自实际检索结果。

## 对照评测

```powershell
npm.cmd run eval:study
npm.cmd run eval:study:model -- --limit=1 --variants=quick,compare
```

支持 `direct,quick,compare,no-memory,no-knowledge` 五个变体。后两项保持比较工作流，只关闭记忆或检索。四个场景分别覆盖静音声源、低音密集排列、明确尾音偏好、带依据的铺底设计。

默认20次脚本对照调用真实浏览器音频引擎，报告写入 `evals/reports/agent-study-scripted-latest.json`。脚本特意给基线和完整流程不同的策略，只验证机制、约束与测量管道，不能当作真实模型提升幅度。真实模型需配置 `.env`，报告写入独立的 `agent-study-live-latest.json`，不会降级为脚本。

报告区分执行完成、场景目标达成、约束校验、修正发生、耗时、实际用量，以及待人工评分的盲听结果。关闭能力的对照未满足目标不是测试执行错误。应重复真实模型实验，比较成本和方差，再填写简历中的改善数据。

现有单元测试验证伪造依据/来源、候选去重、修正次数限制、保留字段、锁定及旧存储迁移；浏览器测试验证反馈与偏好的显式保存和删除。

## 避免耗尽轮次

完整工程已随请求提供，简单修改可直接注册候选。相同参数的读取、校验、候选注册和渲染请求会复用成功结果，即使模型更换了调用 ID，也不会重复创建候选。达到探索预算后关闭工具调用，预留最多两轮输出最终 JSON。

若模型仍持续请求工具，系统仅返回本轮已注册且通过约束和工作流校验的候选，并明确标注可能只满足部分要求；有渲染器时仍需成功渲染后返回。没有有效候选、比较步骤未完成、请求取消或渲染失败时不会伪装成功。总超时和工具次数上限不变。
