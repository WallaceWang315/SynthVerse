# Vital 源码与网页引擎接入记录

日期：2026-10-08。用户源码位于 `vital/vital`，保留原目录，没有修改其代码、资产或许可。

## 本轮研究与实现

已检查 `Makefile`、`src/synthesis/synth_engine/sound_engine.h`、`src/synthesis/producers/`、`src/synthesis/effects/`、`src/common/load_save.cpp` 和 README/LICENSE。

源码引擎包含原生音符事件、波表、采样、调制连接、效果链及过采样机制；保存过程不只是几个控制值，还包含波表状态、采样、LFO 形状与调制映射。因此把网页参数直接写成 `.vital`，并不能保证它在 Vital 中重现声音。

当前网页采用独立的 Web Audio 实现，参考声源—滤波—包络—调制—效果的模块组织，没有复制 Vital DSP。内置波表为自主生成的 Fourier 谐波，不是 Vital 波表或官方音色。

| 模块 | 本轮可运行能力 | 原生接入仍需补充 |
|---|---|---|
| 声源 | 3 振荡器、基础/谐波波表、齐奏、移调、声像、噪声、低八度 | 任意波表、采样、频谱变形、FM 等 |
| 滤波 | 双串联滤波、4 种类型、截止/共振/包络深度 | Vital 滤波模型与完整路由 |
| 调制 | ADSR、包络2、双 LFO、8 连接、力度调制 | 自定义 LFO、完整源/目标、映射曲线与更多连接 |
| 效果 | 失真、合唱、镶边、相位、延迟、混响、EQ、压缩 | Vital 原生算法、参数范围与可重排效果 |
| 演奏 | 键盘点击、电脑键盘短音试听、片段复音渲染 | 持续按键、MIDI/MPE、滑音和演奏模式 |
| 预设 | SynthVerse v2 音色 JSON 与4个自主起点音色 | Vital/Serum 原生预设读写与差异报告 |

快捷控制保持常显；其他模块在“深入设计声音”中分组展开。功能覆盖扩大不意味着达到 Vital 的声音等价或完整功能。

## 为什么当前没有直接运行 C++ 核心

本机检查未发现 `emcc`、CMake 或 clang++ 可执行文件。Vital 的现有 Makefile 使用原生目标和 SIMD 选项，并没有现成网页构建入口。本轮未安装该工具链，也未声称编译成功。现有网页保持可运行，原生引擎接入应作为单独的技术验证。

## 后续移植的可验收步骤

1. 从 headless 与 synthesis 入口分离 DSP，定义窄接口：初始化/销毁、音符开关、设置参数、加载状态、处理音频块。
2. 先验证原生构建，固定编译器、依赖与版本，再验证 Emscripten 的 WebAssembly/SIMD 编译。不能把修改 SIMD 标志视为移植已经完成。
3. 将音频块处理放入 AudioWorklet，预分配缓冲区，避免在实时处理回调中做 JSON 解析和堆分配。
4. 在相同采样率、参数、输入 MIDI 下，与原生引擎比较输出、音符时序、尾音和 CPU；增加浏览器兼容、负载与异常恢复测试。
5. 接入真实预设前，验证版本迁移、波表/采样/调制恢复。对不支持字段明确拒绝或提示，不能静默降级成基础波形。

若浏览器移植验证困难，可以先验证本机原生 headless 渲染服务；它适合候选试听与导出，但网络往返使它不能替代低延迟网页演奏。
